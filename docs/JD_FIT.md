# 70 条评测 JD 的能力匹配、差距与外部依赖盘点

复核日期：2026-10-22（Asia/Shanghai）。逐条原文、分类与能力标签见 [JD_ANALYSIS.md](JD_ANALYSIS.md)、[jd_review.json](../data/manifests/jd_review.json)；本文的机器可读结果见 [jd_fit.json](../data/manifests/jd_fit.json)；复现命令见第 6 节。

**范围**：只回答两个问题——当前仓库的能力画像与 70 条 JD 有多重合，以及各外部项目被借鉴了多少。这是**设计覆盖**，不是录用概率，也不是效果证据；真实 API 与人工金标尚未执行，当前不包含模型微调，因此“落地效果”证据为 0。

## 1. 口径

70 条 JD 共 486 个能力标签（多标签，合计大于 70）。给当前仓库的 14 类能力各打一个覆盖等级：1.0 = 本仓库有一等实现；0.5 = 只覆盖一个子场景；0 = 明确非目标。每条 JD 的得分是它全部标签等级的算术平均，70 条再平均；不按公司、级别或标签数量加权。

| 能力 | 等级 | 依据 |
|---|---|---|
| benchmark | 1.0 | τ 零售 114 任务、54/20/40 划分、清单与哈希可追溯 |
| metric | 1.0 | 官方 reward 与六层 Grade 分开保存，不合成单一总分 |
| judge | 1.0 | 证据约束的固定 Judge、盲标与复核协议；当前不训练小 Judge |
| agent | 1.0 | τ 轨迹、工具调用、环境重置、最早错误事件 |
| calibration | 1.0 | 任务/种子配对 Bootstrap、ECE/Brier、人工一致性入口 |
| contamination | 1.0 | 父任务同源分组；test 不进入优化、水位或模拟题 |
| safety | 0.5 | 只有 RED 隐私/越权层，不是对抗安全 benchmark |
| multimodal | 0.0 | 明确非目标，不用文本项目冒充多模态能力 |
| longctx | 0.0 | 明确非目标；由另一个基座评测项目负责 RULER |
| code | 0.0 | 明确非目标；由另一个基座评测项目负责 HumanEval+ |
| data | 0.75 | 盲标导入导出；480 条标注尚未执行；模拟题规则已写、尚未生成 |
| training | 0.0 | 当前实验不包含模型微调 |
| platform | 0.4 | CLI、manifest、报告、冻结/比较；不是调度/看板平台 |
| diagnosis | 1.0 | 六层、cause、error_type、earliest_error_event、证据支持 |

benchmark / metric / judge / agent / calibration / diagnosis 六项核心方法学均为 1.0；差距主要来自岗位广度（多模态/代码）、平台化程度和真实训练闭环。

敏感区间为 53.8%–71.8%：把 platform、training、data、safety 四个判断项在严/宽口径间变动（见 jd_fit.json 的 sensitivity）。“条件覆盖”是剔除 multimodal/code/longctx 后的覆盖，只用于诊断差距是否来自岗位广度，不作为主分数。

## 4. 外部依赖盘点

先给能直接量到的代码事实：

- 仓库内 **0 行 vendored 上游源码**：`external/` 被 Git 忽略，τ-bench 以 editable 安装后直接调用；当前 tracked external 文件 0 个。
- `src/retail_eval` 共 1741 行；直接 import 上游框架的模块为 `agent.py`、`optimize.py`，共 363 行，占 20.9%；其余 1378 行（79.1%）只依赖标准库/httpx/pydantic。
- tests 共 580 行。
- `references.lock.yaml` 固定 5 个源码 commit；τ/DeepAgents/GEPA/DSPy 为 MIT；AWM 锁定树未声明 LICENSE，因此未并入代码。当前锁文件不含 Judge 微调框架。

运行时职责：

| 职责 | 提供方 |

| 环境、任务、官方评分、模拟用户 | τ-bench v1.0.1 |

| 提示优化与候选搜索 | GEPA |
| 六层评分、证据校验、归因与报告 | 本项目 |

按“能力份额”归一化的借鉴估值（**作者估计**，单项约 ±3–5pp；不是代码行测量）：

合计：**运行时框架 45%**（τ-bench 26 + DeepAgents 10 + GEPA 9）、**方法/论文 20.5%**、**仅参照 1%**、**自研 33.5%**；即外部约 66.5%、自研约 33.5%。

两个口径不矛盾：按代码行，自研 79.1%；按能力份额，自研 33.5%。框架提供可运行骨架，自研提供评测协议、证据契约、隔离与治理。引用时请同时给出两个口径，避免把“用了框架”说成“自研框架”，也避免把“代码自己写”说成“能力全部自研”。

## 5. 使用边界

- 可以写：“基于 τ-bench v1.0.1 零售环境与 DeepAgents 被测 Agent，用官方终态和盲标区分尺子变化与订单终态，自研六层 Rubric、证据约束 Judge、任务隔离和模拟题筛选规则。”
- 不要写：“自研 benchmark / 自研 Agent 框架 / 自研优化算法 / 自研评测平台”。
- 不要写：“提升 X%”——真实实验尚未执行；本文只描述设计覆盖。
- 相似度是设计覆盖，不是录用概率；真实 API、人工金标与测试 40 上的 v1/最终版必须另行回填。

& .venv/Scripts/python.exe scripts/analyze_jd_fit.py
