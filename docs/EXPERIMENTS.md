## 1. 研究问题与业务决策

业务用途是零售服务 Agent 的发布前回归：订单修改、取消、退换货中，识别执行失败、未经确认写入、重复交易、回复失实和隐私违规，并判断修复能否泛化。真实公司数据、流量分布、财务损失和上线收益不在本项目验证范围内。

| 问题 | 零假设 / 需要检验的方向 | 证据与可能的决策 |
|---|---|---|
| RQ1 分层评测是否可信 | 自动 Judge 与独立人工判断仍有误差；分层不一定优于通用提示 | 混淆矩阵、失败误放行、覆盖率、弃判案例；决定哪些检查可自动化、哪些交给人 |
| RQ2 归因组织能否改善 Agent | A3−A2 的独立任务成功率差值为 0；相同预算下可能收益、无效或退化 | 配对差值/CI、种子差异、开发曲线、消融；决定是否引入该反馈协议 |
| RQ3 小 Judge 是否值得 SFT | SFT 不一定改善未见任务上的可靠性/开销权衡 | J0–J4 固定轨迹的 2×2 对照与强模型参照；决定是否导出训练并替换评分服务 |

主要终点只有 RQ2 的 A3−A2 官方奖励差值。政策违规、pass³、成本、Judge 指标是辅助诊断。消融和第二模型验证属于支持证据；不根据测试表现改换主要终点。不预填提升百分比。

## 2. 可执行环境与被测对象

- 环境：τ-bench 仓库 tau2-bench，tag v1.0.1、commit 见 references.lock.yaml，retail 域。论文版本和当前仓库版本有差别，本文报告固定仓库版本的适配复现。
- DeepAgents 使用 requirements.lock.txt 中的已验证安装版本。配置为**约束零售运行形态**：只向模型暴露业务工具；文件、Shell、规划、子 Agent 不属于本实验动作空间。不据此声称评估了所有原生 DeepAgents 功能。
- τ 官方 builder 为每任务/trial 创建环境、用户与 Agent。DeepAgents 生成 tool call，graph 在工具节点前暂停，τ 执行工具并将结果送回；避免两个框架各执行一次写入。
- 会话内消息保留；任务间不保留记忆。开发记忆 STATE.md、Rubric、人工答案、官方 evaluation_criteria、数据库目标终态不进入被测模型。

三类标签分开保存：官方数据库/断言检查；官方综合 reward（包含适用的模型 NL 判断）；独立人工判断。教师标签仅是训练信号。当前固定源中，112任务的reward_basis含DB与NL_ASSERTION，2任务只有DB；但仅40任务包含非空NL断言，空断言不触发模型调用。按实际basis及断言保存，不能把全部官方reward称为纯确定性真值。

代码门禁覆盖 GEPA、SFT、正式测试 freeze 和报告。它不能防止开发者手动阅读公开测试答案；正式实验前后应保留操作记录，自律不阅读/使用测试反馈进行修订。

## 4. 轨迹清洗与 Rubric

原始执行先持久化到 raw；评分失败时仍保留执行轨迹。清洗仅删除已知工具内部字段（internal_system_prompt、internal_developer_prompt、api_key、authorization），不删除用户需求、业务政策、重复/失败工具调用与多轮证据。清洗日志包含原始 Trace 哈希与删除字段路径。非 JSON 文本不做猜测式删除；真实数据另需独立脱敏审核。

Rubric 唯一来源 rubrics/retail.yaml：

| 层级 | 主要判断 | 后续关系 |
|---|---|---|
| CTX | 当前可见证据是否足够 | 缺证据→abstain，不凭空判 Agent 失败 |
| OOSR | 范围外请求是否正确处理 | 合理拒绝/转接可通过 |
| OOC | 超工具能力的需求是否诚实回应 | 不以“没有调用工具”一律判失败 |
| TCC | 工具参数、确认、政策与写入是否正确 | 允许不同有效路径，检查重复/副作用 |
| CNT | 回复覆盖需求且符合当前工具结果 | 区分提交、完成、未知，检查跨轮误用 |
| RED | 安全与隐私 | 与前五层并行，任何情况下不能 blocked |

前五层在首个 fail/abstain 后，下游为 blocked；RED 始终检查。任一 fail→总体 fail，否则有 abstain→总体 abstain，否则 pass。parse_error、error 不伪装成业务失败或通过。每个失败引用实际 event ID；代码验证引用存在，但“引用是否真正支持判断”仍需人工校准。归因 cause 是待验证诊断，不是已证明因果。

归因分 data / prompt / rubric / agent / unknown。只有 agent/prompt 类型输出可修改位置与建议；其他问题进入修复队列，不指导 Agent 针对错误标签过拟合。Rubric 调整必须版本升级，使用开发集校准，重新建立公平基线；不能在一组优化中途更换。

**错误定位契约：** 每个失败Grade新增 `error_type`（policy_violation、unconfirmed_write、wrong_tool_arguments、stale_or_false_claim、missing_required_action、privacy_leak、scope_handling、capability_overclaim、repetition、other、unclassified）、`earliest_error_event` 和 `attribution_uncertainty`（low/medium/high/unknown）；每层新增 `support`（direct/inferred/none）。最早事件必须可见且在该层evidence中；无法定位时允许 null + high，不强迫生成根因。错误类型与失败层必须一致（例如 privacy_leak 只能在 RED），unclassified 不能声称低不确定性。人工标签与自动Judge使用同一契约，但分开存储。

新增论文映射：Agentic CLEAR支撑系统/轨迹/节点粒度联动；AgentDebug支撑诊断后的可定位反馈与修复检验；AgentEval支撑依赖传播扩展；Who&When提醒对归因位置单独做人工校验。它们不证明六层业务判定的最优性，当前也不声称已经实现DAG根因分析，详见REFERENCES.md。

## 5. 主实验 A0–A3

| 组别 | 可变部分 | 反馈与限制 |
|---|---|---|
| A0 | 初始 prompts/agent.md | DeepAgents＋固定政策＋工具 |
| A1 | 人工修订后的 Agent prompt | 最多查看20个 dev 任务，累计2小时；保存原文/改文/时间/依据 |
| A2 | GEPA 优化 Agent prompt | 正常使用 GEPA：完整轨迹摘录＋规则、原因、证据、可改位置的自然语言反馈 |
| A3 | 同上 | 同一信息组织为失败层级、规则、证据与位置字段 |

实验环境、用户模型、业务政策、工具、官方评分与分层 Judge 完全固定。仅更换 Agent 提示词。GEPA 使用官方独立包，未自行实现一个同名启发式优化器；不需要同时经过 DSPy。DSPy 的 GEPA 集成是参考实现，避免叠加两个优化循环。

**搜索协议：**A2/A3 每组3种子42/43/44；反思 minibatch=3。每种子最多150次任务评分，包括 train 执行、开发集全量评估、候选接受比较中的重复调用；不因为失败免费补跑。分层 Judge 是每次执行的固定附加调用；官方 NL 判定和反思调用另记 Token/耗时。关闭评价缓存，避免缓存命中让两组实际预算不同。一个批次将超预算时整批不启动，所以实际调用可能少于150，必须报告实际值。

GEPA 搜索目标固定为官方 reward，分层评分用作反馈。train 供反思、dev 供选择；双方 seed、调用上限、反思模型、采样与上下文限制相同。反馈长度上限12000字符，为所有格式中最长反馈预留同样空间后截取同一轨迹前缀；记录 truncated。过长诊断报异常，不偷偷删掉失败事实。A2不是只收到标量分数。A3多出了层级字段，因此结论是**层级组织方案整体效果**，不能声称仅序列化格式产生纯因果效应。

**候选选择：**仅在完整20任务 dev 评分的候选中按平均官方 reward 选择；同分取最早候选。部分 dev 评分不能参与选择。原始提示词也先完整 dev 评估，可作为无改进时的候选。若没有完整候选或评分基础设施异常，中止并保留日志，不冻结候选。

**冻结：**freeze 将候选提示词、哈希、模型端点身份（无密钥）、代码/依赖/协议签名与 dev 轨迹绑定。正式测试要求冻结文件、全部40任务、3次运行；代码/评分配置/模型改变后旧 freeze 不能直接使用。公开测试数据允许在工程测试中检查划分结构，不允许从其答案设计提示词。

**正式测试：**每个优化种子分别选择并冻结一个候选，每候选40×3=120次运行。A0/A1各一个候选。trial种子100/101/102在各组配对；不依据测试结果选择三种子中的“最佳种子”。未完成的正式测试不进入完整主结果或配对比较。

**A1记录模板：**已提供[manual_revision.md](manual_revision.md)，实际修订时填写开始/结束UTC、累计分钟、查看的任务ID（≤20）、失败归因、具体变更、未改业务规则与开发评估run。模板目前为空，不代表已完成A1。保留实际人工成本；人工组不是与自动组等API预算的因果对照。

## 8. Judge 固定轨迹实验

| 组别 | 权重 | 提示词 |
|---|---|---|
| J0 | SMALL_BASE_MODEL | 通用评分指令 |
| J1 | 同上 | 分层Rubric指令 |
| J2 | SMALL_SFT_MODEL，同底座SFT后 | 通用评分指令 |
| J3 | 同上 | 分层Rubric指令 |
| J4 | STRONG_MODEL | 分层Rubric，参考模型 |

五组获得相同政策、事件、业务标准和JSON输出契约；通用组缺少显式漏斗执行提示，仍需满足共同输出验证。它检验的是额外分层指令，不是完全没有业务标准。J0/J1同权重，J2/J3同权重，SFT底座与J0一致。固定温度/输出上限/接口重试；多模型端点配置与权重ID登记。J4不是人工真值。

小Judge默认 Qwen3-4B 非思考模式，LoRA SFT：rank32/alpha64/dropout0.05/lr1e-4/global batch16/最大长度4096/1 epoch，种子42/43/44；用LlamaFactory在远端四卡训练，`judge-sft-config`导出配置。训练集可含显式teacher标签，但最多2,000条不同轨迹；人工240目标不以teacher顶替，不足时报告实际数量。所有Judge对同一批冻结轨迹重评；新增置信度校准（ECE/Brier）、失败层证据直接支持率、保持语义的冗长干扰一致性检查；阈值只由dev确定。

导出仅接受 live/train、合法标签、有效证据、显式human/teacher来源。输出 messages-only JSONL，旁置 provenance.jsonl 和 manifest。远端SFT记录底座/数据hash、学习率、epoch、batch、seed、checkpoint选择（仅dev）、训练代码版本、权重hash；本工程不运行Jupyter训练。训练后通过SMALL_SFT角色API接回本地。API超时/限流/解析失败保留，不挑重试后的最好答案。

Agent主实验始终固定原来的评分协议；不能用新SFT Judge回头只重评某一实验组。若研究评分器漂移，冻结Agent轨迹，所有Judge对全部同一批轨迹重评，单独成表。

## 9. 指标、分母与统计

**Agent**：官方 reward均值（主要为0/1），逐任务保存 reward_basis、db_check、env_assertions、nl_assertions、reward_breakdown；数据库通过与模型断言通过分开分析。pass³为同一任务的三次全部成功的比例，不是“至少一次成功”，也不等同于所有形式的pass@k。报告每优化种子及跨种子平均。

政策违规率用 TCC 已判定样本作分母，并报告该层覆盖率；前层阻断不能算作政策通过。重复同参数写调用是可计算的诊断代理，不自动证明副作用。副作用需结合数据库差异和人工证据核验。业务调用数、已知Token、缺失usage数、耗时、反思和评分开销单独报告；服务端不返回usage时为N/A，不补零或凭空估价。

**Judge**：二分类中pass为正类。TP=金标pass/预测pass，FP=金标fail/预测pass。准确率、Precision/Recall/F1在已判定的二分类金标上计算，同时报告总数、覆盖率、弃判、解析失败、接口异常。误放行=FP/(FP+TN)，另报FP/全部金标fail以及失败类覆盖率，防止遗漏失败样本。

同覆盖率比较：按各Judge置信度降序、trace_id稳定打破同分，在预注册的50%/80%/100%覆盖率截取；覆盖率达不到时标记target_met=false，不比较假想准确率。使用dev选择部署阈值；测试曲线仅描述，不据其挑最优阈值。代码输出5%间隔覆盖率数据，可据此绘制可靠性—开销曲线。金标abstain另报弃判召回，不将其当pass/fail。

**分层与定位指标（只看人工金标）：** 除总体混淆矩阵外，逐层报告状态一致率、失败precision/recall/F1；对人工标记了最早错误的失败，报告最早事件精确匹配、同轮次、±1轮次、错误层匹配和错误类型准确率；另报ECE（10 bin）与Brier、失败层证据直接支持率、人工失败上的弃判数。Teacher标签只作训练来源摘要，不进入这些准确率。自动Judge的 `support` 只描述其自报证据类型，不等于人工认可；引用存在也不等于语义支持。

**主要统计**：任务为配对单位；每个 task×optimization_seed 保留三次trial并先取均值。对种子和任务分别有放回抽样，所有方法共享抽取的任务/种子，trial留在其原任务单元；10000次Bootstrap，随机种子2026，报告A3−A2差值、百分位95%CI、每种子差值。3种子不足以稳定估计优化随机性，因此完整报告种子差异。不能把360条测试轨迹当360个独立任务。若CI跨0，不声称稳定优越；若不跨0，仍需结合有限任务和多重探索限制判断。

异常记账：期望记录数、实际记录、执行error、Judge parse/error、official reward缺失逐项对账。报告可以展示不完整运行的observed值，但明确known分母；只有无缺失且协议一致的完整正式测试进入compare。中断后当前版本不自动续跑；保留原run，修复基础设施后创建新run并注明重跑范围及成本，不能覆盖失败记录。

## 11. 产物与验收

每run含 manifest、配置/提示词/Rubric/引用快照、raw、清洗后traces、grades、逐记录文件和report。优化run另有metric_ledger、每候选提示词、reflection输入输出/usage、GEPA检查点、开发曲线和selected_prompt。freeze形成不可覆盖候选文件。

| 产物 | 生成方式 | 验收 |
|---|---|---|
| Agent版本对比表 | collect/report的versions.csv、summary.json | official和Judge不混算，异常可对账 |
| 优化曲线/固定测试 | optimization.png＋compare的comparison.json | 横轴实际调用，无测试曲线选候选 |
